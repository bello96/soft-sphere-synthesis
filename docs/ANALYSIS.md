# 软球合成玩法：参考素材分析与实现原理

本文是对 `ReferenceResources/` 里两段录屏、三张截图的逐帧分析，以及《噗叽水球》这个网页版的实现说明。

说明：参考素材来自 Steam 上的软球合成游戏《sobosuba》（开发者 keepeetron）。本项目是**同类玩法的原创实现**：物理手感、瞄准发射、碰撞合成这些玩法机制按参考素材复现；美术、界面、名称、配色顺序、规则细节都是重新设计的，没有使用原作的任何素材。

文档分两次写成：第 1 节是第一版（v1）时对参考视频的观察；第 2 节是 v1 完成后，针对"不像原作、不能算是球、张力不明显"这条反馈做的第二次对照分析，以及据此重做的物理模型（v2）。v1 完整保留在 `versions/v1-pool/`。

---

## 1. 从视频里看到了什么

逐帧抽取方法：两段视频（48.6 秒横屏桌面版、19.5 秒竖屏手机版）用无头 Chrome 解码，按 2–12 帧/秒导出联系表，再对关键片段（重击、合成）做细看。

### 1.1 核心循环

| 观察点 | 细节 |
| --- | --- |
| 待发射队列 | 容器顶部有一条"候场通道"，常驻 4 个球。球在通道里被挤成扁椭圆（长宽比约 2.5）。 |
| 补球规律 | 每发射一个球，就有一个新球从通道左侧或右侧的闸口滑进来，通道里始终是 4 个。 |
| 选择与瞄准 | 按住通道里任意一个球，球被白色描边选中；拖动时出现一支白色箭头，箭头越长力度越大。方向不限。 |
| 合成 | 两个数字相同的球一接触就合成为两倍数字；新球先闪白，约 1–1.5 秒内褪回自身颜色。刚合成的球短时间内不会再次合成，之后碰到同值的球会继续连锁合成（视频中出现 32→64→128→256 的连锁）。 |
| 数值 | 从 1 开始（1、2、4、8……131072），每个数值一个固定颜色。 |
| 危险提示 | 两侧墙壁中部各有一个半圆标记和竖向计量条；堆到标记高度时边框变黄、计量条亮起。 |

### 1.2 画面特征

- 容器内部是纯黑（或极深的颜色），球是**平涂**的饱和色，没有渐变和高光。
- 球与球之间是一条细细的黑缝（背景透出来），没有其他描边，所以球堆看起来像一幅马赛克。
- 球上的数字是深色的小字，大球上的数字也不大，像盖上去的小印章。
- 轮廓不是完美平滑的曲线，大变形处能看到细小的棱角。

## 2. 第二次对照分析：v1 为什么不像原作

### 2.1 反馈与资料

反馈原话：虽然也能反弹、也能形变，但是体态、颜色、容器状态、游戏画面、小球的形变都和原作不一样，"不能算是小球了，涨力不是那么的明显"。

查到的原作资料：

- 原作官网 [sobosuba.com](https://sobosuba.com/) 与 [Steam 商店页](https://store.steampowered.com/app/1946560/sobosuba/)：玩法描述是"用力射可以把别的球推开、挤进狭窄的缝隙，轻轻射可以精确摆放而不打扰其他球"。官网和商店页都没有给出技术细节。
- [80.lv 的报道](https://80.lv/articles/godot-powered-ultra-squishy-merge-game-you-ll-want-to-play)（2026-08-12）引用了开发者对物理的说明：每个软球是"一圈小刚体圆珠，像一串珠子"；"每个球对珠子施加皮肤力，让相邻珠子保持紧绷，再加一个沿法线把珠子推出/拉回的压力，让体积回到某个目标值"。
- 这和经典的压力软体模型（Matyka 与 Ollila 2003 年的 *A pressure model for soft body simulation*，[教程](https://panoramx.ift.uni.wroc.pl/~maq/soft2d/index.php)）是同一类：弹簧皮 + 按气体状态方程计算的内压。

关键信息：原作的球是**被压力撑开的、绷紧的皮**，体积是"目标值"，不是硬约束。

### 2.2 测量方法

在无头 Chrome 里把视频画到 canvas 上读像素，按颜色分割出单个球（数字造成的空洞会被填上），逐帧计算面积、长宽比（等效椭圆的二阶矩）和质心。换算成本项目的世界单位（水箱宽 600）：横屏视频的水箱内宽 462 像素（×1.30），竖屏视频约 500 像素（×1.2）。

本项目这边用 Node 直接加载 `config.js` 和 `physics.js` 做同样的实验（自由晃动、撞墙、静置、被压），指标完全一致。

### 2.3 测量结果

| 指标 | 原作（视频测量） | v1 | v2（现在） |
| --- | --- | --- | --- |
| 自由晃动周期（"64"，半径约 60–70） | 约 1.1 秒 | 0.33 秒 | 1.04 秒 |
| 小球晃动周期（"4"/"8"，半径约 35–45） | 约 1.1 秒（只测到下限） | 0.33 秒 | 0.75–0.84 秒 |
| 每半个周期剩下的晃动幅度 | 约 86% | 约 72% | 85–88% |
| 大幅拉长（约 2.2–2.5:1）时的面积 | 约 80% | 100%（不可压缩） | 约 77% |
| 斜撞侧壁（约 300 横向、480 竖向） | 压成竖条，长宽比 4.2，可见面积约 50% | 长宽比 1.34，面积 100% | 长宽比 2.3，面积 87% |
| 正面撞墙（700） | — | — | 长宽比 2.9，面积 64% |
| 被大球压住的中号球 | 面积 74%，长宽比 1.9 | 面积 100% | 面积 82%，长宽比 2.5 |
| 满载水箱 | 底部球被压扁，整体像泡沫 | 球保持圆形，三角空隙多 | 底部约 80%、顶部 91–98%，堆完全静止 |
| 重力（按球的大小换算） | 约 120–140 | 240 | 140 |
| 最大发射速度（同上） | 约 790 | 1120 | 900 |
| 球的大小（"16"、"512"、"4096"的半径） | 约 50、89、130 | 47、88、129 | 不变 |

斜撞侧壁这一项 v2 仍然比原作"硬"：原作那一下还撞到了侧壁中部的半圆凸起，视频里无法分开两者的影响，所以没有为它单独加大软度。

### 2.4 根因

v1 的模型和原作正好处在两个相反的区间：

| | 原作 | v1 |
| --- | --- | --- |
| 皮 | 几乎不能伸长，预先绷紧 | 可以拉伸，静止时**没有张力** |
| 里面 | 可以压缩的"气"，压力把皮撑开 | 几乎不可压缩的"水" |
| 保持圆形靠什么 | 气压把定长的皮撑成圆（同周长下圆的面积最大） | 每个子步往圆形拉回 0.1% 的"形状匹配" |

由此产生三个具体问题：

1. **形状匹配决定了一切**：每子步 0.001 的回拉相当于一根角频率 19 rad/s 的弹簧，所以无论大小，所有球都以约 0.33 秒的周期快速抖动、很快停下。手感像软糖，不像气球。
2. **没有"涨力"**：皮在静止时长度正好等于圆周，张力为零，面积又是硬约束，所以球没有"被撑开"的感觉；受压时只能改变形状，不能被压瘪再鼓回来。
3. **堆不起泡沫**：球不会被压缩，又被拉回圆形，所以堆在一起时保持圆形、留下三角空隙，而不是像原作那样互相挤满。

### 2.5 v2 的模型

每个球仍是一圈质点，但约束换成：

1. **预张紧的皮**：相邻质点之间的距离约束，静止长度比圆周短 3%（`skinStretch`），所以皮在静止时就有张力 T₀。皮的刚度按"张力 / 应变"设定：张力 T₀ 时应变 3%，受压翻倍时应变 6%，周长基本不变。
2. **可压缩的气**：面积约束带柔度，相当于内压 p = 体积模量 × (目标面积 − 面积) / 静止面积。目标面积比圆略大，使静止时的气压正好等于 p₀，与皮的张力平衡：对正 n 边形，T₀ = p₀ · r · cos(π/n)。所以自由的球正好是半径 r 的圆，而且是"撑开"的。
3. **气压越压越硬**：体积模量按 (静止面积 / 当前面积)² 增长，类似真实气体。满力度撞墙能压到约一半面积，但永远压不成一条线（压成线的环会折叠，之后再也鼓不回来，见 2.7）。
4. **气体阻尼**：对面积变化率加 XPBD 阻尼（时间常数 0.02 秒），避免球像心跳一样持续"呼吸"。
5. **去掉形状匹配**：圆形完全由气压维持。数字的旋转角仍用形状匹配的最优旋转来算，只是不再施加回拉。
6. **气压随大小变化**：p₀ = `pressure0` × (r / r₀)^1.25。大球的晃动更慢（1.6 秒），小球更快（0.75 秒），中号约 1 秒。
7. **阻尼分两档**：飞行中的晃动阻尼很小（0.5/秒，飞出去的球会一直晃），接触其他物体时较大（3/秒，球堆能稳定下来）。

参数选择：先扫描体积模量和气压，看晃动周期、撞击压缩、被压时的面积三项；再在满载水箱里比较"气压 9.5"和"气压 6"两种观感。气压 6 时格子更贴合、三球交汇处的空隙更小，晃动周期也最接近原作，所以采用 6。

### 2.6 发射：被压扁再弹开

原作的球在候场通道里被挤扁，一发射就在"竖长 ↔ 横扁"之间大幅度晃动。本项目没有照搬候场通道，而是做成：**拖动瞄准时，发射器里的球顺着瞄准方向被压扁**，长宽比为 1 + 1.2 × 力度（满力度约 2.2:1）。松手后球沿飞行方向弹成长胶囊，再来回晃，同时皮兜式的"前快后慢"初速度（`stretch`）继续加大拉伸。这个压扁也让玩家直接看到力度大小。

### 2.7 这次修掉的问题

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 满力度射向角落的小球被拍成一条线，0.8 秒后才恢复 | 线性的软气压挡不住球顶部以 1120 的速度砸下来，环被压平并在两端折叠 | 气压随压缩非线性变硬；面积变化加阻尼；最大发射速度降到 900。同一局回放对比：同一时刻从 14% 变为 56% |
| 发射器里新出现的球持续"呼吸"，面积在 ±30% 间振荡 | 生成时从 0.3 倍充气，激起面积模态，而面积几乎没有阻尼 | 气体阻尼；生成时直接把质点环放到缩小后的尺寸 |
| 合成后的新球偶发心形凹口，一直不消失 | 合成射线的起点落在两个父球之间的缝里，沿缝的射线什么都打不到，在并集轮廓上切出一道深豁口；第一帧皮收紧时豁口两侧交叉，环自相交 | 射线起点改为落在某个父球内部；对射线距离做形态学闭运算，填平窄豁口；并集轮廓按弧长均匀重采样；新球的皮按出生时轮廓的周长起步，再随合成动画收回 |
| 自相交的环无法自己恢复 | 气压和皮只沿环作用，解不开已经交叉的环（v1 靠形状匹配解开） | 每帧用转向数（转角和 / 2π）检测，发现后把同一批质点按绕质心的角度重新串起来：位置、轮廓范围和动量都不变 |
| 满箱时新球可能生成在别的球里面 | 发射器补球不检查出生点 | 出生点被占用时先把挡路的球推开，空出来再补球 |
| 自动对局机器人的结果每次不同 | 音效调用 `Math.random()`，但被真实音频时钟节流，消耗的随机数个数取决于运行时间 | 机器人运行时静音 |

修复前后，自然对局中环自相交的次数从每 200 秒 2–32 次降到 0。

### 2.8 画面

按原作的画面特征重做，配色、容器和界面都是自己的设计：

- 水箱内部为接近黑色的深紫墨色，外围页面略浅；容器是一圈厚的圆角框（不是原作的切角框和侧面半圆标记）。倒计时期间，框体和虚线一起变成珊瑚红并闪烁。
- 球是平涂色，没有描边、渐变和高光；轮廓比质点环外扩 1.8，相邻两球之间露出约 2.4 个单位的深色细缝，和原作截图里的缝宽相当。（最初只外扩 0.6、缝宽约 5 个单位，在手机上缝隙太明显，后来收窄。实测接触中的质点与对方的边几乎总保持 6 个单位，近于 3.6 的样本不到十万分之三，所以相邻轮廓不会互相盖住。）
- 配色：2 到 1024 沿色环走一圈（珊瑚红、橙、向日葵黄、青柠、薄荷、天蓝、蓝、紫罗兰、兰紫、粉），2048 起换一组更浅的颜色，顺序保证相邻数值的色相不相近。
- 数字用深墨色，是球自身颜色的深色版，字号随球缓慢增大但有上限；数字跟着球旋转，并按 70% 跟随整体变形一起被挤扁、拉长。
- 去掉了水波、焦散、光束、气泡、浮绳等泳池主题元素；合成时仍然闪白后褪色，受撞击时只有很淡的提亮。

## 3. 实现细节

技术选型：原生 JavaScript + Canvas 2D，**不需要构建、不依赖任何库**，双击 `index.html` 即可在浏览器里玩。物理引擎完全自写。

### 3.1 文件结构

```
index.html          页面与界面
css/style.css       界面样式（深色主题）
js/config.js        所有可调参数与配色
js/physics.js       软体物理引擎（核心）
js/game.js          游戏规则：发射器、队列、瞄准、合成、计分、危险线
js/render.js        Canvas 渲染：水箱、平涂软球、瞄准线、警戒虚线
js/fx.js            特效：飞溅、光环、得分飘字、被吸收的残影
js/audio.js         WebAudio 实时合成音效（无音频文件）
js/color.js         颜色工具
js/main.js          启动、输入、界面绑定、固定步长主循环
dev/physics-lab.html 物理调试页（点击投球，观察质点与统计）
dev/tools/          无头 Chrome 自动对局机器人与界面点检
versions/v1-pool/   改版前的版本
assets/fonts/       Fredoka 字体（SIL OFL 许可，见 OFL.txt）
```

### 3.2 求解顺序

质点数按周长决定（约每 10.5 个单位一个，16–110 个）。每帧 10 个子步，每个子步依次：积分 → 皮 → 气 → 形状（只在发射器压扁时生效）→ 防翻折 → 建网格 → 碰撞 → 深穿透救援（每帧一次）→ 墙 → 由位置差得出速度并施加阻尼。每帧结束时检查环有没有自相交。

- **防翻折**：每条边与质心组成的三角形面积不得低于静止值的 12%。修正量做了动量中和。
- **碰撞**：每个质点与其他球的边做"带厚度"的最近点检测（表皮半厚 3）；均匀网格做宽相，每个子步重建。对同一个球只取最近的边，最近点落在顶点上时用顶点伪法向判断里外。摩擦在位置层面按静/动摩擦处理。
- **深穿透救援**：对落进别的球里面的质点做点在多边形内测试，沿"对方中心 → 质点"方向推出去，并把上一帧位置同步平移，不凭空注入速度。

### 3.3 能量耗散

- **形变阻尼**：只衰减相对刚体运动的速度分量，飞行中 0.5/秒，接触时 3/秒。
- **气体阻尼**：衰减面积变化率，抑制"呼吸"。
- **滚动阻力与接触阻尼**：只在球接触墙或其他球时生效，让球堆停得住。
- **空气阻力**：很小，飞行中的球基本保持动量。

### 3.4 发射

- 在水箱里任意位置按住拖动：方向 = 发射器指向手指，力度 = 拖动距离（越过一段死区后线性增长，可在中心松手取消）。
- 拖动时球被往反方向轻轻拉回，并顺着瞄准方向被压扁（见 2.6）。
- 瞄准时用质点模型预测前约 1.2 秒的轨迹（含墙面反弹），画成渐隐的点线，并在预计碰撞处画出虚线落点。
- 补球前先确认发射器位置是空的。

### 3.5 合成

1. 碰撞检测中发现两个同值球接触，且都不在冷却期，记为候选对。
2. **并集轮廓**：从一个在父球内部的点向各个方向发射射线，沿射线只穿过两球连续覆盖的部分（只跨越表皮细缝，不跨越更宽的空隙，否则会把夹在中间的第三个球吞进去），遇到邻居就截断；再填平窄豁口、按弧长均匀重采样。新球一出生就是横跨两个旧球的"花生形"。
3. 校验：并集面积必须合理，新轮廓不能有点落进邻居。不合格时改用备用方案：把较大旧球的表皮按弧长重新采样，从当前大小"充气"到新尺寸，被吸收的球画成一个缩向它的残影。实测约 95% 的合成走并集方案。
4. 新球的尺寸系数从并集大小在 0.2 秒内缓动到 1，皮的长度从出生轮廓的周长一起收回，于是出现平滑的收缩加晃动；同时闪白、冷却 0.32 秒、获得一个向上的小冲量，并对周围的球施加一圈向外的冲击波。
5. 1.6 秒内的连续合成计为连击，得分 = 新数值 × 连击数。

### 3.6 渲染

- **轮廓**：经过质点的平滑闭合曲线（中点二次贝塞尔），沿法向外扩 1.8；凹角处外扩得更少，避免轮廓打结。
- **布局**：水箱高度按屏幕比例在 860–1060 之间取值，只在开局时（世界重建时）重新适配；画布大小则随舞台区域实时缩放。舞台尺寸用 ResizeObserver 监听，而不只靠窗口的 resize 事件，原因见 3.8。

### 3.8 微信内置浏览器

- **水箱压住上下栏（已修复）**：iOS 微信会在页面完成首次布局之后才给出底部安全区（home 条那一截，34pt），而且不触发窗口 resize 事件。舞台因此变矮，画布却还是旧尺寸，居中后上下各溢出约 15pt，盖住了分数栏和底部按钮。手机浏览器里安全区在加载时就已确定，所以没有这个问题。修法是监听舞台元素本身的尺寸变化；`ui-check.mjs` 用 `Emulation.setSafeAreaInsetsOverride` 复现这一过程并检查。
- **预防性处理**（没有真机验证）：`color-scheme: dark` 防止安卓微信深色模式给页面强制变色；`-webkit-text-size-adjust: 100%` 和 `WeixinJSBridge` 的 `setFontSizeCallback` 让微信的"字体大小"设置不放大页面文字；拦截 `touchmove`，免得在画布外拖动时把整页拉下来，露出"网页由…提供"。

### 3.7 验证

- 自动对局机器人（`dev/tools/bot.mjs`）用真实游戏逻辑、确定性随机种子连续打 200–240 秒，每帧检查：质点落入他球、环自相交、被压瘪卡住（面积低于 45% 超过 0.5 秒）、最大膨胀。最终版本 3 个种子各打 240 秒：零穿透、零自相交、零压瘪，瞬时最大压缩到约 50%，最大膨胀 1.11，每局约 165 次合成，单步物理平均约 1.4 毫秒。
- 界面点检（`dev/tools/ui-check.mjs`）用真实鼠标和键盘事件，在 390×844、375×603 和 1440×900 三种尺寸下逐项检查（开始、瞄准发射、旧的道具按钮与快捷键已移除、画布始终在舞台内、微信式的迟到安全区、新一局重新适配水箱、静音、暂停、重开、危险倒计时、结束与再来一局、最高分保存）。
- 没有验证过：Firefox、安卓手机与安卓微信、实际的声音输出、真人玩家的难度体验。iOS Safari 和 iOS 微信只有用户的截图。

## 4. 与参考作品的差异（原创设计部分）

| 方面 | 参考作品 | 本项目 |
| --- | --- | --- |
| 视觉风格 | 纯黑容器、切角灰框和侧面半圆标记、方正的科技感字体 | 深紫墨色水箱、厚圆角框、圆润的 Fredoka 字体，配色顺序不同 |
| 发球机制 | 顶部 4 球候场通道，可任选，左右闸口补球 | 单个发射位 + "下一个"预告；拖动时球在发射器里被压扁 |
| 数值起点 | 1 | 2 |
| 失败条件 | 侧壁半圆标记 + 计量条（推断） | 警戒虚线：有球在线上方停留超过 3 秒即结束，期间虚线和边框变红、显示倒计时并有提示音 |
| 道具 | 一排工具按钮 | 没有道具（摇一摇、换球、透视都已去掉），只靠发射和合成 |
| 音效 | — | 全部 WebAudio 实时合成：碰撞声随球大小变调，合成音沿五声音阶随等级升高 |

主要参数都集中在 `js/config.js`：重力、气压、体积模量、皮的预拉伸、阻尼、尺寸增长率、发射力度、合成冷却等，改完刷新页面即可看到效果。
